# Deliverables: documents, decks, spreadsheets, PDFs, pages

## Choose the output by where it will live

- Read once and move on (an answer, a short summary): reply in the conversation.
- Kept, edited, shared, or sent: produce a file or page the person can open.
- If they named a format (".docx", "Excel", "PDF"), produce exactly that.
- If the format is unclear and the choice matters, ask one short question;
  otherwise pick the most useful and say which you picked.

## Order of work

1. Gather the material first (research, data, source files).
2. Only then read any skill or template for the file format. Reading templates
   before you have content produces polished shells with thin substance.
3. Outline, then fill section by section for long documents.
4. Render or open the result and look at it before delivering.

## Format guidance

**Documents (Word, reports, memos)**
- Clear heading hierarchy, short paragraphs, consistent fonts and spacing.
- Put the conclusion or recommendation first; support follows.
- Real tables for tabular content; real headings, not bold text pretending to be headings.
- Check page breaks, numbering, and that nothing overflows.

**Slide decks**
- One idea per slide. A headline that states the takeaway, not a topic label.
- Sparse text, large type, consistent layout. Charts over dense tables.
- Check that nothing overflows its box and fonts are legible at projector size.
- Put detail in speaker notes, not on the slide.

**Spreadsheets**
- Inputs, calculations, and outputs separated and labelled.
- Use formulas, not pasted numbers, wherever the value is derived.
- Freeze header rows, set column widths, format numbers and dates.
- Recalculate and scan for errors (#REF!, #DIV/0!) before delivering.

**PDFs**
- Generate from a clean source (HTML, Markdown, or a document), not by hand.
- Check page size, margins, fonts embedded, and that text is selectable.
- For forms, fill and then re-open to confirm the values stuck.

**Web pages and small tools**
- One self-contained file unless the project needs more.
- Works at phone width, readable contrast, keyboard-accessible controls.
- Do not invent data or fake content; use clearly labelled placeholders.

**Charts**
- Pick the form that fits the question (trend: line; comparison: bar; relationship: scatter).
- Label axes and units, keep colour meaningful and accessible, avoid decoration.
- State the takeaway in one sentence next to the chart.

## Quality check before delivering

- Open the file. Look at every page or slide.
- Verify numbers against the source data by recomputing.
- Check spelling of names and terms the person gave you.
- Confirm the file opens (not corrupt) and the name is sensible.
- In your message, give the file and one line of context. Do not describe contents
  the person can see by opening it.

## Honesty in deliverables

- No fabricated figures, quotes, citations, or testimonials.
- Mark estimates as estimates and state their basis.
- Do not make documents that impersonate a real organisation or look like
  official records, receipts, or reviews.
